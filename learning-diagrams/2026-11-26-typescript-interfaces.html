Combining contracts. A class can implement several interfaces with implements A, B, and an interface can extend several with extends A, B. A class can extend one base class.

Object shape

Which user fields are required?

The lesson models a user record with UserDetails, the same kind of shape you can use to describe an expected API response.

UserDetails contract
  • id: numberRequired
  • name: stringRequired
  • profession: stringRequired
  • experience: numberRequired
  • age?: numberOptional
  • salary?: numberOptional
  • readonly offerLetter: stringRequired · readonly
Lesson object

userOne

id: 1

The lesson prints 1, ANUREET using name.toUpperCase(), and 15, then assigns experience = 18. It omits both optional fields.

Compile time and runtime. TypeScript rejects assigning a new offerLetter through this reference. The interface is erased when TypeScript emits JavaScript, so JSON validation requires a runtime check. With strict null checks, reading an omitted optional field can produce undefined.

Two ways to build a bank account

Both implementations satisfy BankAccount. deposit adds to this.balance and returns no value. withdraw returns false without changing the balance if the amount exceeds it. Otherwise, it subtracts the amount and returns true.

Beyond the lesson · Node.js test runner

Test the contract and the behavior

These examples use built-in node:test and node:assert/strict. Copy the lesson to lesson.ts and export the types, fixture and classes in the imports below. Compile the TypeScript and run the emitted test file with node --test. The API example uses sample JSON in place of an HTTP response.

Shared test imports
import { test } from 'node:test';
import assert from 'node:assert/strict';
import { ApolloHospitals, CheckAccounts, bankUserOne } from './lesson.js';
import type { BankAccount, Hospitals } from './lesson.js';

Check that methods can chain

Input A fresh ApolloHospitals instance.
Outcome Each instance method returns the same object, so the next call can be chained.

test('hospital methods return the same instance', () => {
  const hospital: Hospitals = new ApolloHospitals();
  assert.strictEqual(hospital.bestPractices(), hospital);
  assert.strictEqual(hospital.hospitalGuideLines(), hospital);
  assert.strictEqual(hospital.safetyMeasures(), hospital);
});

Run the same check on two implementations

Input Both account types start with 100.
Outcome After depositing 25 and withdrawing 20, an attempt to withdraw 106 returns false and leaves 105.

const accounts: [string, BankAccount][] = [
  ['literal', { ...bankUserOne, balance: 100 }],
  ['class', new CheckAccounts('Test account', 100)],
];
for (const [name, account] of accounts) {
  test(`${name} preserves the balance on rejection`, () => {
    account.deposit(25);
    assert.strictEqual(account.withdraw(20), true);
    assert.strictEqual(account.withdraw(106), false);
    assert.strictEqual(account.balance, 105);
  });
}

Check a response field at runtime

Input Sample JSON for the UserDetails.id field.
Outcome A numeric id passes. A string id causes an assertion failure. This check covers one field.

function assertNumericId(raw: string) {
  const body = JSON.parse(raw);
  assert.strictEqual(typeof body?.id, 'number');
}

test('JSON id must be numeric', () => {
  assertNumericId('{"id":1}');
  assert.throws(() => assertNumericId('{"id":"1"}'), {
    code: 'ERR_ASSERTION',
  });
});
